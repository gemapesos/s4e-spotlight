# S4E Spotlight behavior

What each command and screen does, in detail. The [README](../README.md) covers building and loading the extension.

- The shortcut toggles the palette and focuses its search field.
- Type to filter commands; use the arrow keys to change selection and Enter to choose. The selected row shows ↵, commands that open a new tab show an external-link icon, and a footer lists the keys for the current screen next to the current store.
- Every screen below the command list has a back button with a breadcrumb (for example Commands / Open case IDs) and a footer with its keys and main action. Screens slide in from the side they came from, rows fade in when a screen opens, and one highlight glides between rows; all motion stops under reduced motion.
- Choosing **Open case IDs** switches the palette to a multiline text field.
- Paste text containing one or more standalone 11-digit Case IDs. Duplicates are ignored in first-seen order.
- Detected IDs appear as chips under the field, with a count of ignored duplicates. Press Enter or choose **Open 3 cases** (the button counts what it will open) to continue; Shift+Enter inserts a line break.
- Batches of 11–50 IDs require confirmation. More than 50 IDs are rejected in both the palette and background worker.
- Each case opens in a background tab in the same Chrome window, leaving the current tab selected.
- If Chrome fails partway through a batch, the extension closes tabs created by that attempt and reports any tab it could not close.
- Case tabs use `https://sellercentral.amazon.com/cu/case-dashboard/view-case?ref=sc_cd_lobby_vc_v3&ie=UTF&caseID=…`.
- Choosing **Open shipment IDs** provides the same multiline workflow for standalone `FBA` plus nine-character shipment IDs, including IDs embedded in Seller Central links.
- Shipment IDs are normalized to uppercase and deduplicated before opening background tabs at `https://sellercentral.amazon.com/fba/inbound-shipment/summary/{shipmentId}/contents`.
- Choosing **Search SKUs** provides the same multiline workflow for merchant SKUs pasted one per line, or separated by commas or tabs. Values longer than 40 characters are ignored. Each SKU opens a background inventory search at `https://sellercentral.amazon.com/myinventory/inventory?…&searchTerm={sku}`.
- Choosing **Bulk removal** takes up to 50 merchant SKUs in the same multiline field (one per line, or separated by commas or tabs), with no confirmation step because it opens a single tab. Using an open Seller Central tab (or opening one), it finds each SKU in unfulfillable inventory, matching case-insensitively, and checks how many units are available for removal. It then opens Amazon’s Create removal order page in a background tab, beside the current one, with only the removable SKUs filled in. A Summary screen shows how many SKUs were included, the next S4E removal order ID (the same one the report uses), and every skipped SKU with its reason: not in unfulfillable inventory, or Amazon’s removal status, such as already scheduled for removal. **Go to removal** (Enter) switches to that tab. The method, address, quantities and removal order ID are chosen on Amazon’s page, and the extension never submits the order. If Amazon doesn’t report eligibility for a SKU, that SKU is included and the summary says so, because Amazon’s form checks it again.
- Choosing **Open Time Out** opens its Google Sheet in the background, then opens the prefilled Google Form as the active tab with its Date set to the current local calendar date. Prefill values come from the Time Out form settings page. If either tab cannot be created, the extension attempts to close any tab created by that request and reports the error.
- Choosing **Generate reports** opens the S4E Spotlight window on its Reports tab, where you choose what to include and confirm once, under the current store: Unfulfillable, Seller Feedback, Stranded, Suppressed, and Shipping Queue, all checked each time. Space, Enter or a click toggles a section, and **Generate report** in the footer (or Command+Enter / Ctrl+Enter) starts it. Nothing is opened or loaded until then. Generating uses an open Seller Central tab, or opens `https://sellercentral.amazon.com/` if none is open. If that tab is not signed in to a store, the window asks you to sign in, with **Open Seller Central** and **Switch store** actions. After a store session is confirmed, it loads the chosen sections from that tab: unfulfillable listings and then removal eligibility for each SKU/FNSKU pair, every lifetime 1–3 star Feedback Manager entry (up to 20,000; Amazon’s page cursor lets twelve chains read different stretches of dates at once), stranded inventory from Fix stranded inventory, search-suppressed Manage Inventory listings with available quantity (with each SKU’s listing-quality issues for the suppression reason), and FBA inbound shipments from the Shipping Queue API. Unchecked sections are never requested, have no progress row, and are left out of both workbooks. While it runs, each section shows a spinner and its progress, then a check and its row count; Escape stops the run and goes back. The window keeps the finished report and offers **Download** with a small debug button (document icon) beside it. If a section loads only partly (for example, more unfulfillable listings or feedback than could be read), the window lists what is missing under the progress rows; the raw workbook also notes it above that sheet. **Download** saves the Sheets workbook, `{Current Store} - {dd-mmm-yyyy} - Sheets.xlsx`, formatted for pasting into the monthly account workbook, using the last store switched to from Switch store or Unknown. The debug button saves the raw workbook, `{Current Store} - {dd-mmm-yyyy}.xlsx`. Those tabs use the workbook headers UnfulfillableDisposals, Stranded, Feedback, SuppressedLE, and Shipping Queue. Stranded, Feedback, and SuppressedLE put the local day before the report in the first column, and every date is dd-mmm-yyyy with no time. Unfulfillable Action comes from removal status: Manual Removal Order Created, Scheduled for Removal, Temporarily Unavailable for Removal, Damaged at the FC - For Monitoring, or Temporarily Unavailable when the units are in a location that cannot process removals. Two of the first three combine as Manual Removal Order Created and Scheduled for Removal, Manual Removal Created and Temporarily Unavailable, or Scheduled for Removal and Temporarily Unavailable. Warehouse damage together with another reason, three or more reasons, or an unrecognized status becomes Multiple Actions Applicable - Refer to Additional Notes for Details. Date of E-Mail and Case ID are N/A, and Case Status is Not Applicable. Removal Order ID is the next S4E id after the latest Removal Order Detail id that matches S4E plus two letters and four digits, and it is written only on rows that are available for removal; every other row is N/A. If that report cannot be read, every Removal Order ID is N/A. Additional Notes keeps the removal-status text. Stranded, Feedback, and SuppressedLE set Action, Other Actions, Date of E-Mail, Removal Order ID where that column exists, and Case ID to N/A, and Case Status to Not Applicable. JMG Outdoors includes a blank Product column on UnfulfillableDisposals. The raw workbook's Daily Tasks worksheet, included with Seller feedback, stacks three sections: Feedback Manager (date, rating, sentiment, order ID, comments, item-as-described, seller response, suppression fields, and feedback ID), then reserved **Disposal Orders** and **Open Cases** titles. The Unfulfillable worksheet includes SKU, identifiers, title, status, price, unit counts by damage type, total unfulfillable quantity, and a Removal Status cell with Amazon’s removal-eligibility wording and unit counts. The Stranded worksheet includes SKU, condition, identifiers, status, price, unit counts, auto-removal date and type, date stranded, stranded reason, and supported actions. The Suppressed worksheet includes search-suppressed SKUs that still have available (or infinite) quantity, with identifiers, status, the localized suppression issue (for example a missing product description), inventory, pricing, and listing fields from Manage Inventory. The Shipping Queue worksheet covers every FBA inbound shipment updated in the last nine months (the reimbursement statute of limitations), oldest first, with the newest at the bottom; each shipment's SKU lines keep Amazon's order. Amazon sorts and filters that list by an update-date index that can lag a shipment’s own last-updated date, so the list is read as 30-day slices of the index, ten at a time and in order, until 250 shipments in a row fall before the cutoff. Slices older than the store’s oldest shipment are skipped. As shipments are read, they start loading their reimbursement-eligibility details from Amazon’s claims (WMSR) endpoints, up to 60 at a time; a shipment with more than 50 SKU lines loads the rest 100 at a time. Required-document types are requested only for eligible shipments with a negative discrepancy, the only lines whose Required Document can be filled. Required-document types are kept for the Sheets tab and are not added as a raw-workbook column. The Sheets Shipping Queue tab uses the same order and keeps only SKU lines whose discrepancy is negative and whose status is Shipment ID - For Monitoring (Automatically Closed After 90 Days) or Shipment ID - New (Send List). Date of Reconciliation is the day before the report, and later rows of the same shipment leave Shipment Date and Shipment ID blank. Required Document is Proof of Inventory Ownership when Amazon asks for an invoice and Delivery when it asks for proof of delivery, joined with AND, and only when the line status is Shipment ID - New (Send List); otherwise it is N/A. Lines that are Outside Reconciliation Window, Investigation Completed, Units Located, another ineligibility reason, or Review Needed are left out, as are shipments whose details could not be loaded. Action, Reimbursement ID, and Amount / Unit are N/A. Date of E-Mail is the day before the report. Case ID is the item case id or N/A, and Case Status is Not Applicable. A shipment with no such line contributes no Sheets row. Each shipment is written as one row per SKU line, repeating the shipment columns, so the sheet can be filtered by shipment or by SKU. Shipment columns: name, ID, contents URL, status, destination and country FC, ship-from address ID, created and last-updated dates (UTC), MSKU count, shipped, received, expected, located, and stowed quantities, calculated quantity discrepancy, workflow ID and type, PO ID, placement status, delivery/shipping window dates and compliance status, need-by date, reason code, finalized status and dates, blocked, partnered import, merchant launched, and ISMS/T2P details. Eligibility columns: details status, claim page URL, reimbursement eligibility and ineligibility reason (for example the nine-month limit), estimated and former eligibility dates, days to wait, eligibility details, inquiry status, text, case ID, creation date and creator, has-discrepancy flag, retail domain, whether claims are allowed, SKU-line count, and total discrepancy quantity. SKU-line columns: SKU, title, FNSKU, ASIN and ASIN link, UPC, barcode type and value, condition, sortable, eligible for research, expected, located, and received quantities, adjusted, reimbursed, clawback, acknowledged, denied, virtually adjusted, and other-received quantities with their receive dates, IAR auto-reconciliations, discrepancy quantity, ineligibility reason, case ID, and reason code. If a later list slice, some shipments’ details, or some SKU lines cannot be loaded, the sheet keeps everything obtainable and adds a note above the headers; affected rows read “Couldn’t load shipment details”.
- **Switch store** opens a searchable list of configured Seller Central stores. Current marks the last completed switch, or Unknown when no current store is recorded. Selecting Current focuses an open Seller Central tab, or opens Seller Central if none is open. Selecting another store starts a dedicated, unfocused Chrome window behind your work. Stores using the same saved credential skip sign-out and sign-in; other credentials use the normal email, password and OTP flow in that helper window. While the helper window is covered by other windows, Chrome reports it hidden and does not deliver debugger input to it, so each step is submitted through the page instead of a trusted click. If a step still does not advance, Needs attention brings the window forward and that step is retried once with a trusted click.
- After the saved store URL loads in a new, fully loaded document with a signed-in Seller Central interface, your own Seller Central tab loads that store URL in place: the tab the switch started from, or else the most recently used one, preferring the original window. It keeps its position, is not activated, and no window takes focus, so you can keep working elsewhere. The helper window then closes, and the other Seller Central tabs in the same normal/private browsing mode are closed. If no Seller Central tab is open, the helper’s tab moves beside the tab the switch started from, also without taking focus; if the original window was closed, another compatible normal window is used, and if none remains, the helper stays as the final window. A failed or unfinished switch leaves the previous Seller Central tabs open. Shared session changes take effect across those tabs during the switch.
- After you choose a store, the palette stays open on a Switching screen laid out like Generate reports: a progress bar and step count, then Sign out, Sign in, Verification code and Open store (only Open store when the same credential skips sign-in), the current step or what Amazon needs, and Cancel switch and Show sign-in. Seller Central can’t be used until the switch finishes, so the screen keeps the page dimmed. Escape or Back hides it while the switch keeps running, leaving a small progress card in the page’s lower-right corner; other tabs where the palette has been used show that card when you return to them. If the palette sent you to unlock first, the page you chose the store on opens the Switching screen once the switch resumes. When the switch finishes, the reloaded Seller Central tab opens on Switched to {store}, which stays until you click or press a key on that page, so the result is waiting even if you stepped away or were in another tab.
- **Manage accounts** opens a full options page. Create a master password first, add shared credentials, then add stores such as **JMG Outdoors** that reference those credentials.
- Account data is encrypted locally with AES-256-GCM. The master password is processed with PBKDF2-HMAC-SHA256 (600,000 iterations), is never stored, and unlocks the vault only for the current browser session.
- **Share vault** on the Accounts page downloads an encrypted copy of every store and credential. A share password, chosen for that file and separate from the master password, is required to decrypt it. Import merges those accounts into an unlocked vault. When no vault exists yet, import creates one protected by a new master password.
- CAPTCHA, manual verification and sign-in errors bring the helper window forward and keep the switch available for manual completion. Accounts shows Needs attention and the current step, with Show sign-in and Cancel controls. Cancel, Lock, Reset and expiry close the helper’s login tab while preserving the old Seller Central tabs. Only one account switch can run at a time.
- On Seller Central login pages, an early passkey guard blocks WebAuthn `navigator.credentials.get/create` calls and reports conditional passkeys and platform authenticators as unavailable, so account switching stays on password login.
- While the palette owns focus, an early event guard reduces interference from host-page text entry, editing, paste, and Ctrl/Cmd+A handlers. Passwords are entered only on the extension’s Accounts page; the palette’s shadow DOM and event guard are not a security boundary for secrets. Space on a list (no text field focused) passes through so it can toggle the selected row. Native input behavior remains intact, and no clipboard permission is requested.
- Choosing an enabled sample command closes the palette without taking another action.
- Escape acts as Back: it first clears a non-empty field, then returns from a nested screen to its parent, and finally closes an already-empty command palette. Escape is ignored while an action is running. Clicking the backdrop or pressing the shortcut again still closes the palette immediately.
- The palette follows the operating system's light or dark color scheme.
